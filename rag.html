Why RAG?
The LLM does not need every document in its context window. Instead, we build a searchable representation of the knowledge and retrieve only the evidence relevant to each question.

02 · Chunking
Turn large documents into retrievable units.
INDEXING

How should we split the documents?

Chunking is a design choice. Too small can lose context; too large can hurt retrieval precision.

Chunking strategies
Fixed-size: split every N tokens. Semantic: split around meaning/topic boundaries. Hierarchical: keep parent sections and smaller child chunks. Good metadata—document, page, section, timestamp, permissions—can be just as important.

Important distinction
Embeddings are not a database and they do not retrieve anything by themselves. They are representations. An index/search system uses those representations to efficiently find candidates.
04 · Indexing
Make your chunks efficiently searchable.
INDEXING

Build retrieval indexes

A modern RAG system can combine multiple retrieval signals instead of relying only on vectors.

Dense index VECTOR

Uses embedding vectors to find semantically similar content.

semantic similarity ANN search
Sparse index KEYWORD

Finds exact words and lexical matches. Useful for names, IDs, codes and rare terminology.

BM25 exact terms
Metadata index FILTER

Restricts results by attributes such as department, date, document type or permissions.

ACL date
Vector database OPTION

One possible implementation. RAG does not require a specific database technology.

index ≠ database
Hybrid retrieval
Dense retrieval is great for meaning. Sparse retrieval is great for exact terminology. Hybrid retrieval combines both signals, often followed by a reranker.
05 · Retrieval
Find candidate evidence for the user's question.
ONLINE

Search the knowledge base

The query can be transformed and searched using dense, sparse, or hybrid retrieval.

What actually happened?
The query is represented in a form compatible with the selected retrieval method. The system retrieves candidates, not necessarily the final context. We may retrieve 20–100 candidates before reranking.
06 · Reranking
A stronger relevance model chooses the best candidates.
ONLINE

Retrieve broad, then rank precisely

A common pattern is fast first-stage retrieval followed by a more expensive reranker.

Why rerank?
Vector similarity is a useful first-pass signal, but semantic relevance can be more subtle. A reranker can inspect the query and candidate together and produce a more precise ranking.
07 · Context construction
Turn retrieved evidence into useful LLM context.
ONLINE

Build the context window

Retrieval results are formatted, ordered and inserted into the prompt alongside the user's question.

SYSTEM: You answer questions using the supplied sources. If the sources do not contain enough information, say so. Cite the source used for factual claims. SOURCES: [1] benefits_2026.pdf · page 12 Employees are eligible for 20 weeks of paid parental leave after the birth or adoption of a child. [2] company_handbook.pdf · page 31 Employees should contact People Operations when beginning the parental leave process. [3] benefits_2026.pdf · page 13 Parental leave may interact with other applicable leave programs. USER: How many weeks of paid parental leave do employees get?
The key idea
RAG is not “search instead of an LLM.” It is retrieval + context construction + generation. The retrieved evidence becomes part of what the model can reason over at inference time.

Important
RAG does not guarantee truth. If retrieval returns irrelevant or incorrect information, the model can still produce a bad answer. Good RAG therefore requires evaluation of both retrieval quality and generation quality.

Production mindset
If a RAG system fails, test: data → parsing → chunking → embeddings → filters → retrieval → reranking → context → prompt → model → final answer. Measure retrieval separately from generation. A beautiful answer is not enough if the system retrieved the wrong evidence.

🧠 The mental model

RAG gives an LLM access to external knowledge at inference time. The knowledge is retrieved dynamically instead of being permanently encoded in the model's parameters.

Offline = indexing Online = query time Evidence ≠ answer

⚡ Three retrieval modes

Dense — meaning-based similarity.

Sparse — exact lexical matching such as BM25.

Hybrid — combine multiple retrieval signals.

🎯 What RAG fixes

RAG can improve access to current, private and large-scale knowledge and can make answers more grounded and traceable. It does not magically eliminate hallucinations.
